# 202 — v0.2 文件库工作流

[English](../../2-implementation/202-v0-2-library-workflow.md)

## 范围

v0.2 在不改变 v0.1 Provider 边界的前提下提高公开发布安全性，并增加可读的共享文件库。

包含：受限展示元数据；仅活动任务状态和分页历史；共享 Inbox/Archive 目录；防冲突的完成下载；安全的重命名、归档、创建目录、列表和统计；带操作者审计的持久内联工作流；面向现有安装的安全升级路径；以及公开发布安全门禁。

不包含：频道历史抓取、任意外部 URL、跨文件系统归档根目录、超出授权用户集合的角色权限，以及完整 Telegram 消息正文。

## 验收

- 任何已跟踪文件、候选归档、Git 对象、远端引用、镜像层、生成的配置或发布载荷都不包含真实凭据、Telegram 会话、用户内容或私有部署标识。
- CI 使用最小权限，并对 push 与 pull request 运行 lint、测试、密钥扫描、依赖检查和公开链接验证。
- 现有安装升级时不会改变已有任务状态；不受支持的较新状态会被拒绝，而不是被修改。
- 展示文本经过规范化且不超过 160 个 Unicode 字符；完整消息正文和敏感 Telegram 对象不会出现在持久化或日志中。
- 新下载完成到 `inbox/`；临时字节保留在 `.partial/` 下；同名文件绝不互相覆盖。
- 中断的完成或整理操作会在安全时恢复；否则保留给运维者检查，且不会删除用户内容。
- `/status` 不显示终态任务；历史、文件、目录和统计有界或分页，并使用可读名称与大小。
- 每个授权用户都能整理共享文件库；重命名、归档和创建目录会记录操作者 ID。
- 完成操作在正常重启后继续有效，并显式拒绝未授权、已过期、陈旧或冲突的输入。
- 路径遍历、绝对路径、符号链接、歧义短 ID、异常文件类型和覆盖尝试都会被拒绝。
- 英文与中文文档、导航、示例和运维说明保持同步。

## 部署与回滚

停止服务并备份 SQLite 数据库、Telegram 会话和下载根目录。在副本上演练升级；只报告数量与失败，不记录内容或私有 Telegram 引用。

部署后验证现有文件和任务、权限、活动任务、共享命令、完成操作及容器稳定性。回滚意味着停止新版本，并同时恢复数据库和下载根目录备份。
