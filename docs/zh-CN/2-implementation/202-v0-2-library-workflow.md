# 202 — v0.2 文件库工作流

[English](../../2-implementation/202-v0-2-library-workflow.md)

## 范围

v0.2 在不改变 v0.1 Provider 边界的前提下提高开源发布安全性，并增加可读的共享文件库。

包含：受限展示元数据、仅活动任务状态和分页历史、共享 Inbox/Archive 目录、防冲突扁平完成下载、安全重命名/归档/建目录/列表/统计、带操作者审计的持久内联工作流、schema 迁移、旧输出对账及公开发布安全门禁。

不包含：频道历史抓取、任意外部 URL、跨文件系统归档根目录、超出授权用户集合的角色权限和完整 Telegram 消息正文。

## 交付顺序

1. 发布隐私、迁移、授权和回滚契约。
2. 审计当前树、历史、引用、镜像和发布制品；轮换已暴露密钥。
3. 增加发布安全自动化。
4. 增加 schema v2 与迁移测试。
5. 增加受限 Provider 元数据及筛选/分页查询。
6. 增加存储布局、目录、整理服务和旧输出对账。
7. 增加持久 Telegram 交互、可读展示和命令。
8. 重组公开文档并执行完整验证。
9. 备份部署状态、演练迁移、部署并验证回滚。

## 验收

- 已跟踪文件、Git 对象、远端引用、镜像层、生成配置和发布制品均不包含真实凭据、Telegram 会话、用户内容或私有部署标识。
- CI 使用最小权限，并对 push 与 pull request 运行 lint、测试、密钥扫描和依赖检查。
- v1 数据库升级到 v2 时不改变已有任务状态；更新 schema 继续被拒绝。
- 展示文本经过规范化且不超过 160 个 Unicode 字符；完整消息正文和敏感 Telegram 对象不会进入持久化或日志。
- 新下载完成到 `inbox/`，临时字节保留在 `.partial/`，同名文件绝不覆盖。
- 中断的完成或整理操作可在不删除用户内容的情况下对账；失败旧文件保留原路径供检查。
- `/status` 不显示终态任务；历史、文件、目录和统计有界或分页，并使用可读名称与大小。
- 每个授权用户都能整理共享文件库；重命名、归档和建目录记录操作者 ID。
- 完成动作在重启后继续有效，并明确拒绝未授权、过期、陈旧或冲突输入。
- 测试拒绝路径遍历、绝对路径、符号链接、歧义短 ID、异常文件类型和覆盖尝试。
- 英文与中文文档、导航、示例、运维说明和本地交接保持同步。

## 部署与回滚

停止服务并备份 SQLite 数据库、Telegram 会话和下载根目录。在副本上演练迁移与对账；只报告数量与失败，不记录内容或私有 Telegram 引用。

部署后验证 schema 版本、文件数、权限、活动任务、共享命令、回调恢复和容器稳定性。回滚时停止新版本，并同时恢复数据库与下载根目录备份。
