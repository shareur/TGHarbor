# 201 — v0.1 核心下载器

[English](../../2-implementation/201-v0-1-core-downloader.md)

## 范围

v0.1 在 Bot 私聊中接收授权用户的任务：

1. 发送或转发一条媒体消息，由 Bot 会话下载该消息。
2. 发送一条公开或私有 Telegram 消息链接；仅当登录用户账号原本可访问时，由用户会话下载。
3. 使用 `/status [job-id]` 查看持久化进度，使用 `/cancel job-id` 请求取消。终态结果也会通过 Bot 尽力通知。

频道历史抓取、多消息范围、权限绕过、Web UI、分布式 Worker 和保证字节级断点续传不属于本版本范围。

## 已实现契约

- 严格 YAML 配置、环境变量覆盖和敏感字段脱敏。
- 在本地终端通过验证码及可选两步验证密码登录；无人值守启动只复用已授权会话。
- 按提交者隔离的 Job API 和版本化 SQLite 模式。
- 原子并发领取、有限尝试、延迟重试、限流等待、取消和重启恢复。
- 支持超时、进度节流、取消轮询、优雅关闭和 Provider 故障隔离的异步 Worker 池。
- 每任务独立本地存储，具有路径及符号链接防护、临时文件、原子完成和崩溃窗口对账。
- 非 root 的 Python 3.15 容器配置，持久挂载配置、状态、会话和下载目录。

## 自动化验收

在安装开发依赖的 Python 3.15 环境中执行：

```bash
python -m ruff check .
python -m pytest -q
```

测试使用假 Telegram 客户端，不需要也不会记录凭据。覆盖配置错误与敏感信息表示、独立 SQLite 领取者、重试耗尽、重启恢复、授权与任务归属、路径穿越与符号链接、写入故障、Worker 超时/取消/关闭、来源会话分流、Bot 命令和应用清理。

## 真实环境验收

以下检查需要运维者自己的凭据，离线测试不能替代：

- 完成 `tgharbor login`，启用两步验证时输入密码。
- 启动 Bot 并确认未授权 Telegram 用户被拒绝。
- 下载发给 Bot 的媒体，以及单条消息链接引用的媒体。
- 观察 `/status`、取消、终态通知和有限重试。
- 下载过程中停止进程，并确认重启恢复。
- 构建镜像，以配置的宿主 UID/GID 运行 Compose；重建容器后确认会话、SQLite 状态和下载仍然存在。

未执行项目必须记录为“未验证”，不得通过推断标记为通过。
