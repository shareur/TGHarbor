# 102 — 文件目录与交互

[English](../../1-architecture/102-file-catalog-and-interactions.md)

TGHarbor v0.2 将下载执行与下载后整理分离。任务描述获取与重试状态；已存储文件记录当前文件名、位置和整理历史。

## 隐私与元数据

Telegram Provider 可提供规范化并截断为最多 160 个 Unicode 字符的消息文本、原始文件名、MIME 类型和大小。TGHarbor 不持久化完整消息正文。受限标题只用于展示，不作为文件名。日志不得包含消息文本、Telegram 链接、凭据、访问哈希或原始 Telegram 对象。

## 授权与目录状态

任务状态与取消仍按请求者隔离。所有授权用户都能列出并整理共享目录；重命名、归档和创建目录会记录实际 Telegram 操作者 ID。共享文件库权限绝不表示拥有其他用户的任务，文件库也不是多租户隔离边界。

完成文件记录与下载根目录一起保存在 SQLite 中。升级会保留现有任务与目录状态；不受支持的较新状态会被拒绝，而不是被修改。升级前必须同时备份数据库和下载根目录。

## 存储布局

```text
downloads/
├── inbox/       已完成、等待整理的文件
├── archive/     授权用户管理的目录
└── .partial/    隐藏的按任务隔离临时文件
```

期望名称会被清理。发生冲突时在扩展名前追加短任务标识，绝不覆盖无关文件。所有路径都保持在根目录以内。绝对路径、路径遍历、空段、符号链接组件和异常文件类型都会被拒绝。完成与整理最终只会留下完整入库的结果，或保留给运维者检查的可恢复文件；中断不会删除用户内容。

## Bot 交互与查询

完成操作包括保留、重命名、归档和重命名并归档。目录选择、新建、确认、取消和分页在正常重启后仍可使用，并在 24 小时后过期。每次操作都会重新检查操作者授权、过期时间和当前目录状态；未授权、已过期、陈旧或冲突的操作会显式失败。

- `/status` 列出请求者自己的 pending/running 任务。
- `/history` 分页列出请求者自己的终态任务。
- `/files`、`/dirs` 和 `/stats` 读取共享目录。
- `/rename`、`/archive` 和 `/mkdir` 允许授权用户修改共享目录，并记录其 Telegram ID。

只有在命令授权范围内唯一匹配时才接受短任务 ID。语法见 [Bot 命令参考](../0-foundation/003-command-reference.md)。

## 备份与回滚

文件系统级备份前先停止服务。SQLite 数据库、其旁文件、Telegram 会话和完整下载根目录必须放在同一个恢复点。回滚意味着停止新版本并一起恢复这些备份；只恢复其中一侧可能导致文件失去关联或被错误识别。遵循 [v0.2 升级与回滚指南](../3-operations/303-v0-2-upgrade.md)。
