# 102 — 文件目录与交互

[English](../../1-architecture/102-file-catalog-and-interactions.md)

TGHarbor v0.2 将下载执行与下载后整理分离。任务描述获取与重试状态；已存储文件记录描述当前文件名、位置和整理历史。

## 隐私与元数据

Telegram Provider 可提供规范化并截断为最多 160 个 Unicode 字符的消息文本、原始文件名、MIME 类型和大小。TGHarbor 不持久化完整消息正文。受限标题只用于展示，不作为文件名。日志不得包含消息文本、Telegram 链接、凭据、access hash 或原始 Telegram 对象。

## 持久模型

Schema v2 为任务增加受限展示元数据和预留 Inbox 名称，并引入：

- 每个完成输出对应一个**已存储文件**，包含根目录相对路径、原始/当前名称、大小、MIME 类型、Inbox/Archive 状态和最近操作者；
- 一个**交互会话**，包含授权操作者、动作、步骤、目标文件、待定输入和过期时间；
- 一个**审计事件**，包含操作者、操作、来源/目标路径和时间。

所有授权用户都能查看和整理共享目录；任务状态与取消仍按请求者隔离。迁移在显式事务中逐版本执行，保留已有记录并拒绝更新版本。迁移后的回滚必须同时恢复数据库和下载根目录备份。

## 存储布局

```text
downloads/
├── inbox/       已完成、等待整理的文件
├── archive/     授权用户管理的目录
└── .partial/    隐藏的按任务隔离临时文件
```

期望名称必须清理；发生冲突时在扩展名前追加短任务标识，绝不覆盖无关文件。所有路径保持在根目录以内。绝对路径、路径遍历、空段、符号链接组件和异常文件类型都会被拒绝。完成与整理使用同文件系统原子移动并同步目录。

Worker 解析并持久化元数据、预留 Inbox 名称、下载到任务隐藏临时路径、原子提交到 Inbox、创建目录记录，然后发送操作按钮。重命名/归档在移动前持久化意图；重启后恢复过程只完成可证明的结果，否则报告冲突且不删除内容。

现有 v0.1 UUID 目录属于旧输出。对账只处理具有已跟踪普通文件的 completed 任务，预留防冲突名称，逐个移动文件，并将歧义或失败项保持原状供运维者检查。

## Bot 交互与查询

完成动作包括 `keep`、`rename`、`archive` 和 `rename-and-archive`。目录选择、新建、确认、取消和分页属于持久交互步骤。回调数据只携带不透明交互 ID 与动作标记；每次回调都重新检查授权、过期时间和目录状态。

- `/status` 显示请求者自己的 pending/running 任务。
- `/history` 分页显示请求者自己的终态任务并支持筛选。
- `/files`、`/dirs` 和 `/stats` 读取共享目录。
- `/rename`、`/archive` 和 `/mkdir` 允许授权用户修改共享目录并记录其 Telegram ID。

短任务 ID 只有在命令授权范围内唯一匹配时才会接受。
